# v0.4 Translation Contract

## 1. Scope

v0.4 introduces a manual-first translation pipeline. It supports Polish and English in
both directions through the same services. Polish-to-English is the primary production
path; English-to-Polish is independently qualified for English source materials.

Translation consumes one exact effective transcript and produces a separate immutable
artifact. It never mutates canonical results or transcript revisions.

## 2. Source and style

The preferred source is the latest manually verified compatible transcript revision.
Raw ASR or an automated-correction candidate may be selected explicitly for experiments,
but must never be presented as manually verified. Source selection uses exact identity
and hashes, not modification time.

Allowed directions are `pl -> en` and `en -> pl`. Style has two independent controls:

```text
register = preserve | formal | informal
discourse = preserve | academic | general
```

Both default to `preserve`. Every mode remains faithful: no added facts, summaries,
omissions, censorship, changed uncertainty, changed speaker identity, or rewritten
argument. Guidance affects idiomatic register and terminology, not meaning.

## 3. Sentence units

Mapping is sentence-to-sentence rather than word-to-word. Deterministic sentenceization
of the selected effective transcript produces units that:

- belong to exactly one stable `speaker_id` and never cross a speaker turn;
- cover a non-empty ordered source-token range exactly once;
- record source token IDs and a source-text SHA-256;
- inherit integer `start_ms` and `end_ms`;
- contain freely ordered target-language text.

Target word count may differ. Future model overlap is read-only context and never changes
unit ownership.

Sentence units are a timing and verification choice, not a claim that Polish and English
sentences align one-to-one. They keep subtitle timing narrower than whole speaker turns,
localize audit failures, and bound future provider retries. Speaker changes remain hard
boundaries, while known abbreviations and legal case forms such as `Battle v. Microsoft`
must not create false sentence boundaries. If later corpus evidence shows that translators
regularly need cross-sentence restructuring, a separately versioned bounded speaker-chunk
unitization may be added; existing artifacts will not silently change interpretation.

## 4. Immutable artifact sketch

The versioned JSON Schema introduced with implementation contains at least:

```text
schema/application version, translation ID/number, job ID, creation time
direction and style
exact canonical result and optional transcript-revision source identity/hash
optional exact parent-translation identity/hash
manual or provider provenance without secrets
units[] { ID, speaker, source token IDs/hash, start/end ms, target text }
warnings and statistics
```

It is a complete snapshot, not a patch. A child records exact parent lineage but remains
independently exportable. Speaker names, colors, CSS, brackets, and italics are renderer
presentation rather than translated transcript data.

## 5. Manual workflow

The staged long-document workflow is:

```text
translate prepare -> edit EWP-TRANSLATION 1 -> preview -> apply -> audit -> export
```

The review exposes immutable source context and editable target text. Damaged IDs, hashes,
direction, style, source coverage, speaker identity, or timing fail closed. Preview and
apply validate identically; apply atomically allocates the next translation number. Batch
prepare/apply use deterministic ordering and per-job failure isolation.

The translation artifact is the target text source for TXT, SRT, VTT, and later TTML/HTML.
Export requires no audio or model. Subtitle planning may split target text only within a
unit's inherited time span and never mutates the artifact.

## 6. Automated translation and benchmarks

Automated translation follows manual gold and always produces a review candidate. Exact
model artifact, quantization, backend, prompt, direction, style, chunking, sampling, and
hardware are recorded.

Initial local candidates are Qwen 2.5 32B Q4, Bielik 11B Q8, Llama 3.3 8B Q8,
MADLAD-400, and NLLB-200. They are candidates, not compatibility, quality, licensing, or
memory claims. Specialized translation models may need different adapters, but must emit
the same validated artifact.

`pl -> en` and `en -> pl` are separate suites with separate manually approved references,
metrics, qualitative review, failure analysis, and rankings. The initial comparison uses
verified source, `preserve/preserve`, and no dictionary. It reports translation quality,
unsupported meaning changes, omissions, terminology/names, sentence and speaker lineage,
latency, resources, request/token/cost volume, retries, and reviewer effort.

Translation quality is semantic, not lexical. A candidate is not penalized for choosing
different idiomatic words from the reference when it preserves meaning. Human assessment
records each exact source unit as `faithful`, `minor_error`, `major_error`, or
`critical_error`, with categorized evidence for mistranslation, omission, addition,
contradiction, changed uncertainty, or changed tone/register. Machine-generated lexical
overlap scores must not be presented as translation accuracy.

Names, approved terminology, spelling, capitalization, and project conventions are a
separate compliance dimension. A convention failure does not silently become a semantic
error, although an incorrect name may independently change meaning. Dictionary-assisted
runs record the explicit dictionary identity and SHA-256 and are never merged with the
no-dictionary baseline.

The implemented first benchmark slice provides:

```text
benchmark translation prepare -> human semantic assessment -> benchmark translation report
```

Preparation stages exact-hash automated candidates and compatible manual references,
requires identical source/direction/style/unit lineage, and creates one private assessment
template per job. Reporting rejects pending units, changed artifacts, incomplete/reordered
unit coverage, and mixed directions. Its content-free output aggregates semantic severity,
issue categories, convention compliance, and dictionary provenance without transcript text.

The first automated-translation execution slice is also implemented. One deterministic
sentence unit is the sole editable owner of each provider operation; the preceding and
following units are bounded read-only context. Operation identity hashes the provider,
model, prompt, direction, style, context width, unit identity, and source hashes. Locally
validated responses must return non-empty target text for the exact owned unit.

The in-process mock provider exercises the complete contract without network or model
access. The first real adapter targets LM Studio's OpenAI-compatible API, uses structured
JSON output, rejects non-loopback endpoints unless explicitly allowed, requires exact-scope
local-API consent before request construction, and records model/prompt/parameters plus
content-free request, retry, latency, token, and provider-reported cost evidence. Per-unit
resume entries are private, immutable, exact-operation-bound, and revalidated before use.
Every published artifact uses LLM provenance and remains a non-final review candidate.
Directory execution uses deterministic result ordering, per-result resume subdirectories,
latest-compatible revision selection, and exit-code-5 failure isolation.

Pilot runtime data is disposable. Every test run creates one dedicated directory with
`mktemp -d` and writes resume state, candidates, exports, assessments, and operational JSON
there. Pilot commands must not add generated files to the private corpus or repository.
After review, record only the required content-free evidence in this document and remove
the temporary directory.

LM Studio supports explicit `json-schema` and `json-text` output modes. `json-text` is the
compatibility path for model/backends that reject a JSON Schema channel: no structured
`response_format` is sent, but the prompt requires a single raw object and the same strict
local schema and request binding apply. Output mode participates in prompt hashing,
provenance, and resume identity. Permanent HTTP rejection diagnostics may expose only the
numeric status code, never response bodies or transcript content.

Manual acceptance never mutates or relabels that candidate. Preparing with an exact
`--parent-translation` prefills a protected review from the candidate only after its source,
direction, style, units, speakers, timing, ownership, ID, filename, and SHA-256 validate.
Applying the edited review publishes a new manual translation whose `parent_translation`
records that exact immutable candidate.

The current private Polish corpus has been edited beyond speech-faithful correction,
including grammar changes. It remains useful for evaluating correction candidates and as
verified translation source, but not for ASR-accuracy claims. The first English corpus
allows artistic translation freedom and therefore gates pipeline structure and manual
workflow only—not translation accuracy. Quality scoring waits for a narrower approved
reference contract. Legacy translated `EWP-REVIEW` copies are migration inputs, not valid
translation artifacts; fresh exact-lineage `EWP-TRANSLATION 1` reviews are required.

## 7. Acceptance

Manual-first slice at the 2026-08-23 checkpoint:

- [x] Schemas and examples validate deterministically.
- [x] Raw and revision source lineage is exact-hash checked.
- [x] Source tokens are covered exactly once and units never cross speakers.
- [x] Manual batch prepare/preview/apply/audit/export round-trips pass in automated tests.
- [x] The private 24-file English corpus prepared from exact compatible Polish revisions
  was mapped into the current scheme, applied, and exported without errors;
  generated SRT/VTT were reported readable.
- [x] Private benchmark content and secrets remain outside Git.

Remaining v0.4 acceptance:

- [ ] Automated output cannot be mistaken for accepted manual translation and can be
  manually reviewed, applied, audited, and exported through the same artifact boundary.
- [ ] Polish-to-English and English-to-Polish provider results remain separate and are
  never collapsed into a misleading combined ranking.
- [ ] A narrower manually approved reference contract exists before any translation
  accuracy claim; the current artistically translated English corpus remains structural
  evidence only.
- [ ] Dictionary, timed-event, TTML, and HTML work passes its dedicated roadmap gates.
