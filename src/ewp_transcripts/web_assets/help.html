GUI workflow

Return to EWP Transcriber

Inspect and dry-run

Choose a server-side file under an allowed root. On WSL, either D:\recordings\episode.wav or /mnt/d/recordings/episode.wav is accepted when that location was included with --allow-root. Inspect reads media identity, streams, channels, duration, and warnings. Dry-run additionally plans immutable outputs but writes nothing.

Build and start a queue

Review dry-run, confirm it, and add the file to the staged table. Repeat for other files under any allowed root while keeping one shared output directory. Remove mistakes before selecting Start queue. Jobs then run one at a time.

LLM-assisted correction

Select the canonical result and a correction output root, then choose the exact provider, model, endpoint, and optional project dictionary. OpenRouter reads its key from the environment that started the GUI; the browser never stores it. Confirm disclosure before generation. The backend and exact model are checked first. Every result is a non-final candidate; use Open candidate in manual review and verify it before applying.

LLM-assisted translation

Select the canonical result and, preferably, its manually verified source revision. Translation from raw ASR or an automated correction candidate remains possible, but the resulting artifact and summary identify that weaker source. Choose the exact LM Studio endpoint/model, target language, compatibility mode, and optional project dictionary. Confirm disclosure before generation. Every generated translation is non-final and requires manual review of meaning, omissions, additions, names, conventions, and style.

Safety and recovery

Refreshing or closing the browser does not stop a job. The server retains current queue state in memory and the application retains atomic filesystem job state. Until cancellation is implemented, stopping the server waits for the active transcription to finish.

Review and verified export

Select a canonical result JSON and one review output root. The GUI creates structured reviews, revisions, and exports paths below it unless manual paths are enabled. Prepare an editable draft, correct text and speaker attribution, save it, and run Preview. Applying requires explicit confirmation that wording, speakers, punctuation, quotations, and sentence boundaries were manually checked. Only the resulting immutable revision is offered to the verified export action. The current saved review is restored after refresh; Clear requires confirmation and does not delete files. In another browser or later GUI run, enter the same persistent output root and select Restore saved review.

What comes next

Translation review, dictionary proposal management, richer recovery/navigation, and remaining operator conveniences will be added in later GUI slices; use the CLI runbook for production workflows not yet exposed here.
